UX/UI Review & Wireframe

Analysis of the house-hunting tool's property list and detail pages, grounded in the four personas (Ashby, Simon, Lorena, George) and their two primary workflows: triage (scan fast, rule out) and evaluation (dig into survivors, discuss as a group).

UX Findings

Critical — No at-a-glance rule-out signal
The three rule-out criteria (affordability, commutes, schools) are scattered across each card in separate sections. To decide if a property is a hard no, the user must read the financial line, scan every commute pill, then check school dots — three separate visual searches per card. During triage of 30+ new properties, this is the primary friction point.
Critical — Affordability indicator missing
The card shows monthly cost (e.g. ~£2,850/mo) but gives no signal about whether that's within, stretching, or over budget. The persona doc says budget is fixed monthly — the user needs a quick ✓/✗ on "can we afford this?" not a number they must mentally compare to a remembered threshold.
Critical — Bottom nav bar obstructs content on mobile
The fixed bottom tab bar (Properties / Favourites / Map) sits at z-index 80 and covers the commute section and action buttons on the detail page. On the 375px screenshot, "George/Secondary School" is partially hidden behind the nav. This blocks the very information users need to make decisions.
Major — Filters don't match workflow
Current filters are "Maybe", "Undecided", "Favourites" — but the personas describe three distinct states: Saved (actively like), Dismissed (hard no), Seen (physically visited). "Undecided" isn't a useful filter; the user wants to see what's new and unprocessed. The filter bar needs: New, Saved, Dismissed, Seen.
Major — Commute pills show destinations, not people
Cards show "Simon/Pimlico", "Simon/Bracknell", "Simon/Dad", "Lorena/Aldgate" — but the user thinks in terms of per-person commute quality, not per-destination. Simon has multiple destinations because he visits different places, but what matters is: "What's Simon's worst commute from this property?" The current display requires mental aggregation.
Major — Floating-point artifact destroys trust
The costs section shows "Total Monthly £3616.1466666666665". For a tool where all four users are suspicious of automated calculations, displaying a raw float is catastrophic. It signals "this wasn't designed for you to trust it." All monetary values must be properly rounded to 2 decimal places or whole pounds.
Major — Provenance display is confusing
Ashby "would click provenance details frequently if they worked" but finds the current display confusing. The existing info icons next to data points aren't clearly interactive and don't explain what data source, when it was fetched, or how the calculation was done. Provenance needs to be inline, scannable, and expandable on click.
Major — Group discussion is a flat textarea
The current "Notes" section is a single textarea per person. But the personas describe WhatsApp-style per-property discussion: "Simon: Booked viewing Sat 10am", "Lorena: Need to check parking". This needs to be threaded, per-person comments with timestamps — not a single text box.
Minor — No "new property" indicator
Freshness helps identify new leads (from personas). When Ashby opens the tool, they need to immediately see which properties they haven't triaged yet. Currently there's no visual distinction between properties seen yesterday and ones just added.
Minor — School dots lack legibility
The dual-dot system (Ofsted dot + walk dot) beside school names is compact but opaque. The dots aren't labelled, so a new user must learn the convention. On the detail page, school info is presented as plain text rows — no visual hierarchy between "Outstanding" and "Good". The Ofsted rating is the primary school quality signal and should be more prominent.
Minor — Missing data shown as raw placeholders
Council Tax shows "? - £?/yr", Sinking Fund shows "£?". These raw placeholders erode confidence. Missing data should show a clear "Not yet researched" state with an action to fill it in, not broken formatting.
Positive — Core data model is sound
The underlying information architecture is right: per-person commutes, school Ofsted + walk distance, monthly cost breakdown, per-person commute cost, provenance tracking. The wireframe preserves all of this — the issue is presentation, not data.
Positive — Detail page tab structure works
The Summary / Commute / Schools / Costs / Notes tab navigation on the detail page is a good information architecture. Users can jump to their priority section. The wireframe keeps this structure but improves the content within each section.

UI Findings

Card density overwhelms scanning
Each list card contains 5–6 distinct sections (address+price, specs, commutes, schools, finance, actions) separated by dividers. At 1280px with a 3-column grid, the cards are dense but readable. At 375px in single column, the vertical length per card is extreme — scrolling through 30 properties means scrolling past hundreds of sections. The redesign condenses the card to focus on the three rule-out signals.
Status actions are hidden behind dropdown
Setting a property's status requires scrolling to the Notes section, finding the Status dropdown, and selecting from a menu. For triage — where the user is rapidly saving or dismissing — this is too many steps. The redesign puts Save/Dismiss actions directly on each card (mobile) or as quick-action buttons.
EPC badge is buried
Energy efficiency directly affects running costs and affordability, but the EPC badge appears as a small pill in the Summary section header. It should be part of the cost/finance signal on the list card.
Map is too small to be useful
The map embed on the detail page is approximately 300x150px — too small to actually understand the property's location relative to stations, schools, or amenities. Either make it full-width expandable or replace with a static location summary.

What Changed and Why

Property List Cards

  • Added verdict strip (Affordability ✓/✗, Commutes ✓/✗, Schools ✓/✗) at the top of each card — addresses the primary triage need. Users can scan 30 cards and immediately identify rule-outs without reading every section.
  • Monthly cost now color-coded against budget — green (within budget), orange (stretching), red (over). Replaces the neutral " ~£X/mo" with a decision-ready signal.
  • Commutes condensed to per-person — shows one pill per person with their worst commute time, not every destination. Detail page shows full breakdown.
  • School quality shown as Ofsted label — replaces dual-dot system with explicit rating text ("Outstanding", "Good") that doesn't require learning a legend.
  • Added "New" badge for recently discovered properties — addresses freshness need.
  • Added Save/Dismiss/Seen buttons on mobile cards — reduces triage friction from 3 taps (scroll, open dropdown, select) to 1 tap.
  • Filters changed to New / Saved / Dismissed / Seen / All — matches the actual three-state model from the personas.
  • Added count badges on filter chips — "Saved (3)" tells you at a glance how many you've shortlisted.

Property Detail Page

  • Sticky summary bar keeps address and price visible while scrolling through sections.
  • Costs section: all values properly formatted — whole pounds or 2 decimal places, no floating-point artifacts. Sub-items (per-person commute cost) shown as indented rows.
  • Provenance shown as inline labels — "Source: TfL API · 26 Jun 2026" appears beneath each data section, not as confusing icons. Expandable on click for full calculation details.
  • Commute section: per-person expandable cards — header shows person name + total time, expand to see route legs (walk → train → walk), cost, and provenance.
  • Schools section: prominent Ofsted badges — rating shown as colored badge (not just text), with distance and walk time. Inspection date shown for trust.
  • Discussion replaces flat textarea — threaded per-person comments with avatars and timestamps. Each person's input is visually distinct and attributable.
  • Status management moved to prominent button group — not hidden in a dropdown. Clear visual states for New / Saved / Dismissed / Seen.
  • Bottom nav bar given proper padding — content area accounts for the fixed nav height so nothing is obscured.

What Was Removed

  • Dual-dot school system — replaced with explicit Ofsted text badges. The dots required learning a convention; text is immediately legible.
  • "Maybe" / "Undecided" filters — these states don't match the workflow. Replaced with states that map to actual decisions.
  • Confusing provenance icons — replaced with inline text provenance that reads naturally.
  • Status dropdown on detail page — replaced with prominent button group that shows all options at once.
