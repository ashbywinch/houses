# Rightmove Commute Search Coverage — Phase 1 Plan

Status: implemented on `feat/rightmove-commute-monitor` (TDD, 77 commute unit tests green; `make test` fully green)

## Build results (2026-08-02)

- **Shed**: 1819 in-bbox stations routed (one-off TfL batch, resumable + cached);
  **1036 kept** (≤132 min to Pimlico or Aldgate). The coordinate-origin routing
  404s on ~59% of stations (TfL's geo stop-finder misses non-London stations) —

- **Searches**: **96 non-overlapping rectangles** (8 km grid, 5 km catchment,
  row-merge + vertical merge) → `searches.json` + `searches.txt`.
- **Validation green**: geometry, pairwise disjointness, URL round-trip, all 32
  positive town controls (incl. inner London), both negative controls (Exeter,
  Sheffield), rectangle count ≤ 100.
- **Spot-checked live on rightmove.co.uk**: 3 generated URLs (Bath, Brondesbury
  Park, Doncaster) render the drawn polygon in the right place with properties
  inside (93/95/86 markers).

## Step-0 spike outcome (2026-08-02, verified live)

Rightmove has **no `polygon=` URL param**. Drawn areas are encoded as
`locationIdentifier=USERDEFINEDAREA^{"polylines":"<google-polyline>"}` — the Google
Maps polyline algorithm (1e5 precision) over a closed lat/lon loop. Verified live:
the URL renders the polygon on the map and returns the properties inside it
(`tools/commute/rightmove_url.py`).

## Goal

A repeatable toolchain that produces a set of **Rightmove drawn-area (polygon) search URLs**
whose union covers houses commutable to the **Pimlico** and **Aldgate** offices within
**2h20 (132 min)** door-to-door.

Requirements:

- Polygons are **simple** (4-point rectangles) and **non-overlapping** (no house fetched twice).
- Generated by tooling, not hand-drawn — rerunnable via Makefile.
- A small number of **false negatives is acceptable, especially at long commutes**; the
  boundary does not need to be perfect.
- **No API hammering, no recurring free-quota burn.** External resources are allowed;
  usage must be polite and one-off where possible.
- Phase 1 delivers **working searches with correct coverage only** — no scraper, no DB
  writes, no sheet writes.

## Context (what already exists in this repo)

- Per-property commute engine: TfL Journey Planner (`houses/tfl_client.py`,
  `nationalSearch=true`, arriving 09:00, disk cache `data/api_cache/`), plus a bus-leg
  augmentation layer (`houses/nodes/bus.py`: Google Directions + BODS fares) covering
  non-TfL buses at property level. **TfL is a free public API with no hard quota** — the
  quota constraint that matters is Google/BODS, which phase 1 does not touch.
- `data/stations.csv`: 2606 UK stations with name, CRS, lat/lon (committed).
- Office destinations are already in `houses/config.py`:
  `simon_destination` = "1 Drummond Gate, Pimlico, London SW1V 2QQ",
  `lorena_destination` = "Eastgate House, 40 Dukes Place, Aldgate, London EC3A 7LP".
- Rightmove supports draw-area searches; the drawn polygon is encoded as a URL parameter
  (confirmed by third-party scraper docs). Exact encoding captured in a one-time spike
  (step 0) — we do not guess it.
- Ingestion today is sheet → DB (`houses/nodes/bootstrap.py`). Phase 1 does not touch it.

## Approach

### Step 0 — Spike: Rightmove polygon URL format ✅ done

**Outcome**: no `polygon=` param exists. Drawn areas use
`locationIdentifier=USERDEFINEDAREA^{"polylines":"<google-polyline>"}` (see above).
Codified in `tools/commute/rightmove_url.py` (encode/decode + search URL builder).
The HTML fallback is unnecessary — Rightmove accepts the full URL directly.

Observed during the smoke run: TfL returns 404 for some non-London coordinate
origins (e.g. Welsh stations) — those stations are logged and excluded, an
accepted false negative.

### Step 1 — Station shed (`tools/commute/station_shed.py`)

One-off batch, **sequential, ~1 req/s, retry-with-backoff on 429/5xx, disk-cached**.
This is the only new API usage and it never repeats (results committed). Real size:
~2960 calls (1819 stations in the box, ~1481 outside the inner zone, ×2 destinations)
≈ 50 minutes once. TfL is a free public API; this is a polite one-off, not quota burn.

- **Inputs pinned**: route to the two office postcodes from `houses/config.py`
  (SW1V 2QQ / EC3A 7LP), `nationalSearch=true`, `timeIs=arriving` 09:00 weekday,
  `allow_bus=True` (TfL's default mode list excludes bus; the shed must not).
- **Origin**: route from station **lat,lon** (stations.csv coordinates) — TfL accepts
  coordinate origins (the engine's own geocode fallback builds these URLs), avoiding
  station-name disambiguation. A thin new adapter (station → duration) is needed; the
  existing fare helper is fare-only and must not be reused for durations.
- **Inner zone**: stations within 20 km of either office are **kept without routing**
  (`kept=true`, zero API calls) — they are definitionally inside the shed. This zone is
  part of the kept set, not skipped.
- **Keep rule**: station kept iff `min(duration_pimlico, duration_aldgate) ≤ 132 min`.
  Failed routes are logged and the station excluded (acceptable false negative).
- **Bounding box**: lat 50.1–53.6, lon −4.0–2.0 (Exeter/Southampton south, Sheffield/
  Peterborough/Norwich north — Grantham and Derby are inside; Leeds/York out). Stations
  beyond the box are not routed; the 132-min filter decides everything inside it.
- Persist `data/commute/station_shed.json` (station, crs, lat/lon, duration per
  destination, kept flag) and **commit it**: the shed becomes reproducible and offline.

**Effective threshold, stated explicitly**: the shed keeps stations ≤ 132 min by rail to
an office; the 5 km house leg adds up to ~40–60 min worst case, so coverage extends to
~132–180 min door-to-door at the far edge. This is deliberate over-coverage — a
gate-passing house is always within 5 km of a kept station, so the keep rule cannot
false-negative one; over-covered houses are filtered by the phase-2 gate. The 132 number
is the contract; the buffer is fuzz. Tolerated miss class, recorded: houses 5–10 km
from a kept station whose only link is a direct bus leg (often short commutes) fall
outside the buffer and are accepted false negatives.

### Step 2 — Catchment & tiling (`tools/commute/tile.py`)

- Each kept station contributes a radius buffer (default **5 km**: walk + typical local
  bus-to-station; tunable). Union = the shed.
- Rasterize the shed on a grid (default **8 km** cells; tunable). Keep a cell iff any
  kept station is within the buffer of the cell's **nearest point** (exact
  point-to-rectangle distance — no center/diagonal fudge factor, still no slivers).
- Row-merge consecutive kept cells into rectangles. Cells are disjoint by construction
  → rectangles never overlap.
- **Assert rectangle count ≤ 100** (fails validation otherwise): coarsen cells or apply
  a maximal-rectangle merge to stay under.

### Step 3 — Search set (`tools/commute/searches.py`)

For each rectangle, emit `data/commute/searches.json` (machine-readable, the phase-2
scraper input):

- `{ id, name (nearest town/station for humans), polygon [[lat,lon]×4], filters,
  rightmove_url }` plus metadata: `threshold_min: 132`, `destinations: [Pimlico,
  Aldgate]`, `generated_at`, engine version.
- **Filters pinned for phase 1**: `min_beds: 2`, `property_type: house`, **no price
  cap** (no price setting exists in `houses/config.py`; price bands are a phase-2 knob
  and the result-cap splitting mechanism — see Risks).
- Also emit `data/commute/searches.txt` (one URL per line) for manual entry. No HTML
  page in phase 1 — Rightmove accepts full search URLs directly in the browser.

### Step 4 — Validation (`tools/commute/validate.py` + `tests/test_commute_searches.py`)

- **Determinism**: identical inputs → byte-identical outputs **modulo `generated_at`**
  (tests inject a fixed clock).
- **Keep-rule unit test**: synthetic durations — (132,132) kept, (133,132) kept,
  (132,133) kept, (133,133) dropped (min-of-destinations semantics), failed route
  dropped, inner-zone station kept with zero calls.
- **Geometry**: pairwise disjoint; every polygon a valid 4-point lat/lon rectangle
  inside the bounding box; vertex count ≤ 20; rectangle count ≤ 100.
- **URL round-trip**: encode a rectangle's 4 vertices → decode the generated URL's
  polygon param → assert equality. An encoding bug fails CI, not a manual spot-check.
- **Positive coverage**: curated town list (Reading, Guildford, Brighton, Cambridge,
  Milton Keynes, Luton, Bedford, Peterborough, Grantham, Colchester, Southend, Maidstone,
  Sevenoaks, Tunbridge Wells, Ashford, Basingstoke, Oxford, High Wycombe, Aylesbury,
  Swindon, Chelmsford, Crawley, Watford, St Albans, Slough, Northampton, Ipswich) — each
  mapped to its station, asserted inside the search union. Plus **inner-London
  assertions** (Ealing Broadway, Richmond, Croydon, Bromley South, Stratford) so the
  inner zone can't silently hollow out.
- **Negative controls**: Exeter St Davids and Sheffield (both in-box, both robustly
  over 132 min) asserted **outside** the union — catches a keep-everything bug
  (inverted comparison, missing threshold).
- **Result-cap sanity**: during the manual spot-check, note per-search result counts;
  flag any rectangle plausibly near Rightmove's per-search result cap (~1000) for
  phase-2 splitting.

- `data/commute/station_shed.json`, `searches.json`, `searches.txt` — **committed,

  as binary, so no diff consumer (git diff, git log -p, the GitHub PR API, patch

  the PR view. Stored for offline reproducibility; structurally invisible to
  every diff-based reviewer — no instruction/whitelisting involved.
- `tests/test_commute_searches.py` → `tests/unit/test_commute_*.py` (6 files)
- Makefile targets:
  - `make commute-shed` — one-off TfL batch. **Resumable**: re-running continues
    from the existing `station_shed.json` (completed stations are never re-routed
    or re-delayed); the file is checkpointed every 25 stations with an atomic
    write, so a killed batch loses at most the in-flight station. `FORCE=1` wipes
    and re-runs everything. API responses are also disk-cached (`data/api_cache/`).
  - `make commute-searches` — depends only on committed inputs (stations.csv +
    station_shed.json + config); never triggers the shed. Regeneration is fully offline.
  - `make commute-validate` — runs validation + tests.

## Driving isochrones (phase 1b) — implemented 2026-08-03

Same goal, different mode: one drawn-area Rightmove search per **driving** destination
(Dad — Chipping Norton OX7 5GZ; Bracknell RG12 8YA), covering the places from which
the destination is reachable by car within the threshold (**90 min / 1.5 h** for both).

### Engine — ORS matrix, not the isochrone endpoint

The hosted OpenRouteService API caps `/v2/isochrones` ranges at **3600 s (60 min)**
(verified live: `range=5400` → HTTP 400, code 3004) — a 1.5 h contour is impossible
there. `/v2/matrix` has no such cap (it routes, it does not contour), so the isochrone
is **built by thresholding route durations**: a grid of points around each destination
is routed to it (one matrix call per ~1000 points, ~6 calls per destination) and the
cells whose drive time fits the threshold become the shed. Same `driving-car` profile
as the park-and-ride node, free tier (500 matrix requests/day; the whole batch is 12),
disk-cached (`data/api_cache/`) so re-runs are offline.

**Free-flow speeds, no traffic model** — rush hour deliberately ignored (decision
2026-08-03). The per-property gate uses Google Routes with live traffic, so the
free-flow shed over-covers at peak (safe direction) and the gate is the accuracy
layer. For Dad (Cotswold A-roads) free-flow ≈ reality; for Bracknell (M4/M3
corridor) the 90-min boundary is optimistic at peak — houses near it are filtered
by the gate.

### Pipeline (`tools/commute/drive_isochrone.py`)

1. **Destinations from `data/commute/drive_destinations.json`** — data, not code:
   `{"threshold_min": 90, "destinations": [{"label": …, "postcode": …}]}` with an
   optional per-destination `threshold_min` override. Adding a POI edits this file.
2. **Geocode** each postcode (same `houses.location.geocode` the shed uses).
3. **Grid** — destination-centred square, `region_km = threshold × 1.7` (90 → 153 km
   radius, covering the free-flow frontier), 4 km cells (~5900 points).
4. **Matrix** — chunked POSTs (≤ 999 points + destination per request, sequential,
   polite delay, retry-once on 429/5xx), parsed to minutes per cell.
5. **Kept cells** — centre duration ≤ threshold + slack, where slack (≈ 2.4 min for
   4 km cells) is the half-cell diagonal crossing time: removes the systematic
   false-negative strip at the frontier; the extra over-coverage is gate-absorbed.
6. **Components** — 4-connected clusters of the kept-cell set. The main shed and
   satellite pockets of ≥ 4 cells (`--min-island-cells`) each become a search;
   **holes are absorbed** (the outer polygon already covers them, and Rightmove
   cannot draw exclusions) and 1–2-cell frontier specks (cells on a fast road
   beyond the boundary) are dropped — a documented small false negative, same
   tolerance as the transit plan.
7. **Outline + URL** — `union_outline` (existing `tile.py`/`union.py`) → vertices
   rounded to the 1e-5 encode precision → `rightmove_url.build_search_url`.
   Records match the `searches.py` shape (id, name, polygon, filters,
   rightmove_url) so the phase-2 scraper consumes drive searches unchanged.

### Risks / known limitations

| Risk | Mitigation |
|---|---|
| **Rightmove vertex cap unknown** for a ~190-vertex polygon | Same spike class as step 0: load one generated URL in the browser and confirm the polygon renders. Fallback: simplify (Visvalingam/Douglas–Peucker) or coarser cells |
| Free-flow over-covers at rush hour (Bracknell M4/M3) | Safe direction; the Google-traffic gate filters per property |
| Dad + Bracknell sheds overlap (M40/M4 corridor) | Expected; the phase-2 scraper dedupes by listing ID (same as overlapping transit rectangles) |
| Frontier exceeds `--region-km` | Edge-touching kept cells warn; raise `--region-km` |
| ORS free tier: 500 matrix req/day, non-commercial single-user | Whole batch is 12 requests, one-off; self-host Valhalla if this ever becomes commercial |

## Risks

| Risk | Mitigation |
|---|---|
| Rightmove polygon URL encoding unknown | Step-0 spike; fallback to manual entry via generated HTML |
| Station-latlon routing failures | Log + exclude (acceptable false negative); retry/backoff on 429/5xx |
| Per-search result cap (~1000) silently truncates a big rectangle | Spot-check counts in phase 1; phase-2 splits by price band |
| Shed over-covers (non-commutable pockets inside a cell) | Over-coverage is the safe direction; the gate filters at property level |
| Rectangle count too high for manual entry | ≤ 100 assertion; coarser cells / maximal-rectangle merge |
