What the designer needs to know
  • This is the current rendering of the new ProvenanceView component, which replaces the old ProvenanceTree.
  • The summary view is shown by default — the "How we got this" (story) and "Full detail" views are available via the toggle.
  • The underlying JSON is what the backend actually returns — no additional data exists beyond this structure.
  • Currently the description field is often empty or contains error messages. Populating it meaningfully is one way to improve the display without backend changes.
  • Backend changes are on the table — we can add new fields to the Provenance model if the design needs them.
  • The formula box is included but lacks explanatory prose — the math is right but the meaning isn't explained.
  • What non-technical users really want to know: Can I trust this? Where did it come from? How fresh is it? What does this number include? What does this calculation mean in plain English?
